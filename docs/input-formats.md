# 输入文件与账户

支持多券商流水输入，各券商独立维护持仓、移动加权成本和逆回购合同，再按证券代码汇总收益、费用和剩余成本。每个券商的输入应属于同一个账户。

支持文件与目录混合输入，也可混合平台。目录读取当前层所有 `.txt` 文件（扩展名不区分大小写），按文件名稳定排序，不递归子目录；没有文本文件的目录会报错。报告文件数按展开后的实际输入文件计数。同一平台的分段流水合并排序后核算。

重叠导出按「平台 + 股东代码 + 证券代码 + 原始交易日期 + 交易行为 + 交易编号 + 流水号」识别重复，交易行为使用统一后的业务名称；交易编号在招商证券对应「合同编号」，在东方财富证券对应「成交编号」。编号保留原文，缺失编号以 `None` 占位，允许交易编号和流水号同时缺失。只去除跨文件重复，同一文件内相同记录的出现次数会保留，多个文件取最大出现次数。不同平台的流水不会互相去重。应输入同一类型的详细流水，不要混入按日归并的汇总记录。报告显示全部平台、文件数、去重后的流水数和重复条数；错误及待确认流水附来源文件与行号。

跨平台合计沿用各账户的托管成交金额，不自动配对抵消转移。两端估值不同时，托管净转入可能仍有差额；这份报告是各账户核算结果的合计，不追溯跨账户原始成本。

招商使用成交日期、业务名称和七项费用列；东方财富使用发生日期、发生时间、交易类别及其费用列。未披露的费用显示为零，仅表示没有独立披露金额，其他费用不再拆分。优先按 UTF-8（含 BOM）
解码，失败后使用 GB18030。按中文两格、ASCII 一格的固定列宽解析空字段，列可以重新排序；每份文件只建立一次金融属性到列的索引。按核算日期排序；同日数字流水号优先按数值排序，再按时间和原始行号排序；其他流水按时间、文本编号和原始行号排序。流水号保留原文。部分记录补到时间、其他记录时间缺失时，不将缺失时间当成午夜提前到买入前。
东方财富逆回购购回使用交收日期核算，；其发生日期可能仍为拆出日，发生时间不用于购回排序。报告日期范围也使用这一核算日期。
证券以代码归组并使用最后一条记录中的名称。金额使用 Decimal。

金额、数量、日期、费用等业务概念由 `FinancialAttribute` 建模；`Platform` 为这些属性提供字段别名、业务名称、购回日期和逆回购数量单位。必需属性缺失时停止解析；可选成交字段保留未知值，时间和编号可省略，未披露费用默认零。证券买卖、托管和逆回购在核算入口要求数量；数量缺失且无法推算时停止核算。未知业务的缺失数量保持未知并显示为“—”，交收资金修正不要求数量。指定交易配对只使用已披露的数量。解析和核算不按平台名称分支。

可预期错误输出到标准错误流。文件读取及编码错误标明文件，表头错误标明文件和可定位的表头行，单元格转换错误附实际列名，核算错误附文件、行号、业务和证券代码。来源定位沿解析与核算链路保留。

## 招商证券成交时间补全

招商证券资金流水未披露成交时间时，可以将“历史成交查询”TXT 与资金流水一同输入。例如：

```powershell
uv run stock-statement earnings "data/招商证券资金流水.txt" "data/2026-11-12 招商证券 历史成交查询.txt"
```

网页中同时选择这两类文件，填写相同账户标签即可。文件按表头识别，不依赖文件名；支持与普通交割单相同的 UTF-8 / GB18030 编码。

历史查询仅补充时间，不作为第二份资金流水：其记录不计入交易笔数、收益、费用或流水重复数。查询文件仍计入输入文件数，不能单独用于收益核算。

匹配条件是成交日期、证券代码、股东代码、委托编号（对应普通流水的合同编号），并同时核对业务方向、成交数量和成交价格。只补普通流水缺失的时间，已有时间保持不变。重复导出的相同时间会合并；同一匹配条件出现不同时间、普通流水缺少股东代码或合同编号、数量价格不符时，保留缺失时间，不猜测，也不拆分聚合流水。

目前仅支持招商证券这个固定宽度历史查询格式。不同券商需要根据其实际导出格式另行接入。股东代码用于识别成交，不替代网页账户标签；同一账户标签内仍按券商独立核算，沪深股东代码不拆成独立资金账户。
