# 项目设计

## 模块与扩展

- `attributes.py`：稳定的金融属性、缺省值及文本转换规则。
- `platforms.py`：平台识别条件、属性列名及业务差异。
- `models.py`：统一流水、证券与逆回购摘要、账户报告；摘要不携带可变合同状态。
- `errors.py`：携带文件、行号、字段及业务上下文的输入和核算错误。
- `loading.py`：目录展开、编码识别、文件读取和跨文件去重。
- `parsing.py`：每份文件的 `HeaderIndex`、行解析及成交字段推算。
- `securities.py`：单券商的证券持仓、托管和分红核算。
- `repo.py`：单券商的逆回购合同匹配、余额核销、费用分摊及计息统计。
- `ledger.py`：流水统计、行政配对、账户现金及业务分派，生成各券商独立摘要。
- `aggregation.py`：按明确字段合并各券商摘要，不合并持仓核算过程或合同。
- `amounts.py`：金额舍入与可见明细的合计规则。
- `reporting.py`：具名证券明细、概览指标、完整性及口径说明，不依赖 Rich。
- `presentation.py`：标题、列格式、颜色、对齐、隐藏规则和 Rich 表格输出。
- `cli.py`：参数解析与异常出口。

增加平台时，在 `PLATFORMS` 注册一个 `Platform`，用 `columns` 将现有金融属性映射到该平台的候选列名，例如 `PRICE: ("成交均价", "成交单价")`。候选按声明顺序选取；未覆盖的属性沿用其标准名称，空元组表示不披露。`identifiers` 指定可唯一识别平台的表头名称；业务别名通过 `businesses` 归一化，购回核算日期通过 `repayment_date` 配置，逆回购编号通过 `RepoIdentifier.TRANSACTION_ID` 或 `RepoIdentifier.SERIAL` 配置。平台构造时验证识别条件、属性映射、日期、编号来源和数量单位。通常无需修改核算代码。

核算状态分别由 `HoldingLedger` 和 `RepoLedger` 管理，结束后生成 `HoldingSummary`、`RepoSummary` 和 `SecuritySummary`。报告投影使用稳定字段与指标标识进行计算，中文标题仅由展示模块定义；舍入值不写回核算状态。

终端中的收益和有符号变动采用红涨绿跌，证券、资金、持仓、费用表头分别使用青色、品红、蓝色、黄色。表格宽度由实际内容决定，重定向到文件时保留所有列及完整文本，默认不输出 ANSI 颜色码。

`tests/fixtures` 提供覆盖核心业务流程的小型 UTF-8 匿名流水和汇总预期，证券编号与名称采用 `000000 / 证券零零`、`000001 / 证券零一` 的对应形式。`tests/factory.py` 中的 `write_statement` 可生成其他固定宽度样本，业务用例独立于本地 `data`、`out` 目录。

## 网页展示

首页支持拖放或选择多个 TXT，使用原有 UTF-8/GB18030 解码、固定列宽解析、跨文件去重及 `ReportView`，没有解析终端输出或在浏览器重新计算收益。原有移动加权成本和费用、分红口径保持不变。金额通过十进制字符串传输，首页金额在后端按与 CLI 相同的舍入规则显示，合计仍为可见明细之和。

上传前为文件填写账户标签。同一真实账户的分段文件使用同一标签，不同账户使用不同标签；每个标签内的券商仍独立核算和配对。原始格式目前不能可靠识别真实账户号，不能自动判定两个同券商文件是否属于不同账户。证券代码保留前导零，UI 使用推定的沪/深/北市场加代码定位；市场由已支持的大陆代码段推定，不支持代码有歧义的境外证券。逆回购没有股票详情入口。

股票详情依次显示策略仪表盘、不复权日 K、未来价格与数量计划、逐笔成交来源。页面支持浅色/深色/系统主题；橙色表示买入或回补，蓝色表示卖出，红涨绿跌单独用于行情及盈亏。B/S 圆角标牌用虚线连接到成交均价的小圆点，日均价由后端按数量加权。通过页面顶部切换 A/B 策略，摘要、图表与交易计划同步更新。选中价位高亮对应线条，通过“查看成交”定位记录。滚轮用于页面滚动，拖动时间轴与价格轴缩放，悬停日 K 可查看开高低收。

## 隐私与 API

上传使用有界 JSON/base64 请求，不使用 `multipart`、`UploadFile` 或临时文件。单文件上限 8 MiB，总解码上限 24 MiB、HTTP 请求体上限 34 MiB；最多 20 文件、2 个并行 POST、8 个内存会话。账户、原文、成交和策略不写磁盘，不写访问日志，不放浏览器持久化存储。浏览器通过 localStorage 保存主题、手数、费率、最低佣金开关及各证券的候选价，不保存账户或交易记录。手动清空删除服务器会话并移除页面数据；会话不因闲置自动过期，服务退出释放内存。页面刷新不会从浏览器存储恢复交易。

API 使用随机会话标识、同源 Host/Origin 校验和 `Cache-Control: no-store`，没有任意路径读取接口；文件名只作展示。生产页面无外部字体、组件 CDN 或 Service Worker。行情请求只发送公共证券标识、日期和周期。

- `POST /api/sessions`：`{"files":[{"name":"流水.txt","account":"账户一","data":"base64..."}]}`。
- `GET /api/sessions/{id}/report`：原报告投影与后端格式化表格。
- `POST /api/sessions/{id}/stocks/{market}:{code}`：账户、现价、候选价、手数与费率；返回两策略、期待、成交、配对、日聚合。`price` 用于现价估值及含费用的当前执行判断，`candidate` 仅用于候选卖价情景。
- `GET /api/market/{market}/{code}?start=YYYYMMDD&end=YYYYMMDD`：公共不复权日 K。
- `GET /api/quotes/{market}/{code}`：公开最新价格、昨收、涨跌额、涨跌百分比、来源和获取时间。涨跌百分比为百分数（`2.5` 表示 `2.5%`），缺少有效昨收时涨跌字段为 `null`。
- `DELETE /api/sessions/{id}`：释放会话。
- `/openapi.json`：类型契约；前端 `api-schema.ts` 由此生成。

## 公共行情与缓存

现价与日线共享进程内的来源限流冷却：遇到 AKShare 限流异常或 HTTP 429（包括异常链中的限流错误）后，该来源暂停网络查询 5 分钟，从后续并行查询候选项中移除，到期后自动恢复。已有有效缓存仍可使用；普通超时、空数据和认证失败不触发限流冷却。冷却期间不主动重试，服务重启会清除冷却状态。

通过 AKShare 并行向东方财富、新浪、腾讯获取股票/ETF 不复权历史日线；当前源异常、网络超时或返回空数据时，终端记录该源、证券代码、日期范围及错误原因，其他源继续查询，采用最先返回的有效结果。支持复权参数的接口明确 `adjust=""`，新浪 ETF 使用原始历史日线接口。单次网络连接与读取等待上限均为 5 秒。成交量统一为手，新浪与腾讯返回的股／份数除以 100，保留不足一手的小数。全部源失败时仍显示报告与计划，允许使用已有旧缓存并显示陈旧状态、更新时间、错误；若无收盘价，估值盈亏保持未知。最终失败或 API 等待超时时，终端另记录请求日期范围、超时上限、缓存路径及错误原因，页面保留固定错误提示。默认错误日志不显示堆栈；使用 `stock-statement ui --debug` 启动时，错误日志附完整异常堆栈。

此前项目没有配置目录约定；UI 采用 Windows `%APPDATA%/stock-statement/cache/market-data/`，其他环境为 `~/.config/stock-statement/cache/market-data/`，启动时打印完整路径。缓存只含公共 OHLCV、数据来源、覆盖日期与更新时间，键区分 AKShare、市场、代码、日周期、不复权和 schema。每根日线的 `source` 记录实际来源（东方财富、新浪或腾讯）；缓存顶层 `source` 汇总全部缓存日线的来源，API 顶层 `source` 汇总返回区间的来源，例如 `新浪、腾讯`，没有行情时为 `暂无数据`。旧缓存没有逐日来源字段时按原有的东方财富来源读取。历史覆盖区间复用，缺口增量补齐；当日范围每 15 分钟刷新最近七日，损坏缓存重新获取，文件通过同目录临时文件原子替换。API 等待行情上限 20 秒；第三方同步请求超时后仍可能在后台完成，其间不再启动第二个行情下载，避免无界线程堆积。

即时价格按 AKShare `stock_zh_a_spot_em`（东方财富）、`stock_zh_a_spot`（新浪）、`stock_individual_spot_xq`（雪球）并行获取，采用最先返回且包含目标证券的有效结果。前两者的全市场快照跨证券共享，成功缓存 30 秒，失败缓存 10 秒；单次网络超时 5 秒，整轮查询等待最多 15 秒；较慢来源在后台完成并更新缓存，尚未结束的下载复用原任务。前两个接口仅覆盖 A 股，场内基金直接使用支持基金的雪球接口。`updated_at` 是获取时间，不冒充交易所成交时间。报价失败不以历史收盘价代替，也不阻断交割单分析；摘要卡片可手动刷新。

网页正文使用本地 MiSans VF 与系统字体回退，金额、价格、数量和图表坐标使用 Inter 与 sans-serif 回退，DOM 数字启用 tabular-nums、lining-nums 及 ss01；项目不下载或捆绑字体。账户概览沿用终端投影的颜色规则。日期显示 YYYY-MM-DD，带时刻的成交记录和行情更新时间按浏览器时区显示 YYYY-MM-DD HH:mm:ss。

账户概览通过明确的 parent 指标归组，主项与其明细显示在同一摘要卡片内。详情显示上传文件名和来源行号。
